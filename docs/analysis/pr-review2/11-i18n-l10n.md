## Özet

i18n **altyapısı** bu PR'ın en güçlü yanlarından biri: 506 çeviri çağrısının tamamı doğru ve literal `'nicepay-payment-gateway'` domain'ini kullanıyor, POT `wp i18n make-pot` ile CI'da yeniden üretilip byte-byte karşılaştırılıyor, `.mo` dosyaları `.po`'lardan taze olmaya zorlanıyor, placeholder/HTML-etiketi denetleyicisi var, placeholder içeren 22 string'in 22'sinde `/* translators: */` yorumu mevcut, çoklu placeholder'ların hepsi `%1$s` numaralandırmasını kullanıyor ve dosya kapsamında hiçbir erken çeviri çağrısı yok (WP 6.7 `_load_textdomain_just_in_time` uyarısı tetiklenmiyor). Buna karşılık **katalogların içeriği** ürünün hedef pazarıyla taban tabana zıt: ürün Kore PG entegrasyonu olmasına rağmen ko_KR ve zh_CN çalışma zamanında 417 kaydın yalnızca 118'ini (%28) çeviriyor; 83 kayıt fuzzy olduğu için `.mo`'ya hiç girmiyor ve bu fuzzy eşleşmelerin bir kısmı anlamı tamamen ters çeviriyor ("Copy failed" → "취소에 실패했습니다."). Müşterinin gördüğü standalone ödeme formunun 18 string'inden 10'u (Ad/E-posta/Telefon etiketleri, tüm placeholder'lar, test-modu uyarısı, modal kapatma etiketi) **üç yerel dilin hiçbirinde** çevrilmemiş. CI kapıları POT tazeliğini ve `.mo` tazeliğini doğruluyor ama POT↔PO msgid bütünlüğünü doğrulamıyor; bir msgid'i dört katalogdan da silmek tüm kontrollerden geçiyor (kanıtladım). Ayrıca para/tarih biçimlendirmesi locale'e tamamen duyarsız (`number_format`, sabit `Y-m-d H:i:s`), NICEPAY ödeme penceresi dili ziyaretçi locale'inden bağımsız statik bir seçenek ve `WordPress.WP.I18n` sniff'i CI'da hiç çalışmıyor.

````php
```js
````

````php
```
Ama gerçek form PHP `number_format()` ile render ediliyor (`templates/standalone-payment-form.php:100`).

````

Sağdaki canlı önizleme `toLocaleString()` sayesinde **50.000 KRW** gösterir. Kaydedip kısa kodu bir sayfaya koyduğunda gerçek form PHP `number_format()` ile **50,000 KRW** render eder. **Etki**

Ürünün en önemli sayısı — ödenecek tutar — hiçbir dilde o dilin sayı konvansiyonuna uymuyor. **Öneri**

```php

    if ( ! $currency ) { $currency = get_option( 'nicepay_currency', 'KRW' ); }
    $decimals = ( 'KRW' === $currency ) ? 0 : 2;
    $value    = round( (float) $amount, $decimals, PHP_ROUND_HALF_UP );

    if ( function_exists( 'wc_price' ) && function_exists( 'get_woocommerce_currency' ) &&
         $currency === get_woocommerce_currency() ) {
        return wp_strip_all_tags( wc_price( $value, array( 'currency' => $currency ) ) );
    }
    /* translators: 1: localized amount, 2: ISO 4217 currency code */
    return sprintf( _x( '%1$s %2$s', 'formatted payment amount', 'nicepay-payment-gateway' ),
```

**Öneri**

1) `maxlength`'i bayt sınırından türetmeyin, kaldırın (bayt kontrolü zaten var) ya da CJK için gerçekçi bir karakter üst sınırına çekin (`maxlength="30"` yerine ad alanı için `maxlength="30"` kalabilir ama tek doğrulama kaynağı bayt olmalı). 2) Hata mesajına sınırı ve mevcut kullanımı koyun:
```php
'fieldTooLong' => __( 'This field is limited to %1$d bytes; the current value uses %2$d.', 'nicepay-payment-gateway' ),
```

